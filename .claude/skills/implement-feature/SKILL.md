Ты получил спецификацию фичи (по `SPEC_TEMPLATE.md` или как текст). Выполни пошагово:

1. Анализ: Прочитай спецификацию, определи затронутые модули; свериcь с `Чертёж.md`, чтобы не изобретать то, что там уже решено (data model, API-контракты, дизайн-токены)
2. Документация: Для всех библиотек из стека — запроси актуальную документацию через Context7 MCP (`use context7`) ПЕРЕД написанием любого кода
3. База данных: Делегируй субагенту `database-architect` создание/обновление таблиц и RLS
4. Интеграции: Если фича касается Salebot/Prodamus/вебхуков — делегируй `integrations-specialist`
5. Бэкенд: Делегируй субагенту `backend-engineer` создание API и серверной логики (кроме вебхуков — см. п.4)
6. Фронтенд: Делегируй субагенту `frontend-developer` создание UI
7. Проверка: Делегируй субагенту `qa-reviewer` проверку всего кода
8. Интеграция: Убедись что все части работают вместе
9. Отчёт: Кратко опиши что было сделано, какие файлы созданы/изменены

Используй plan mode перед началом реализации.
Если спецификация неполная — задай уточняющие вопросы ПЕРЕД началом работы.
Если фича противоречит архитектурным ограничениям из `CLAUDE.md` (напр. просит вызвать Telegram Bot API из приложения) — остановись и уточни у пользователя, не реализуй молча.
